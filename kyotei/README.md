# kyotei — AI舟券 答え合わせ帳

公開ページ: https://hiro0530.github.io/zeroichi-store/kyotei/

- 毎朝 06:45 JST(`.github/workflows/kyotei.yml`): 前日の全レースを答え合わせ → 学習用の履歴を少し足す → (月曜・履歴が育つ間は毎日)学習し直し → 当日の予想 → このフォルダにコミット → gh-pages の `kyotei/index.html` だけを更新。
- `predictions/`(公開時刻つき・公開後は書き換えない。締切が公開時刻より前のレースは採点しない)/ `results/` / `summary.json` / `model.json`(係数と、学習に使っていない期間での検証結果 `eval`)
- 比較の基準は常に「1号艇を毎回」。予想は無料の参考情報で、的中・利益を保証しない。過去の成績は将来を約束しない。20歳未満は投票不可。検証で1号艇を上回れていない期間は、ページにそのまま書く。
- 手動実行: `trigger.txt` の1行目を書き換えてpush(`daily` / `backfill`(履歴を上限つきでさかのぼって作り学習)/ `refit`(学習だけ)/ `exp`(v3の改良候補を1つずつ検証 → 採用した構成を `model_config.json` に書き、学習し直す))。
- 予想には自信度(本命の1着確率 S:70%以上 / A:55%以上 / B:40%以上 / C:それ未満)を付ける。自信度ごとの学習外の成績は `model.json` の `eval.tiers`、公開後の実績は `summary.json` の `tiers`。

## データの出どころと利用条件

| データ | 取得元 | 使い方 | 取得の頻度 |
|---|---|---|---|
| 番組表(B) | BOAT RACE 公式のダウンロードデータ `www1.mbrace.or.jp/od2/B/` | 当日朝の予想、学習 | 毎朝 当日分+前日分の2ファイル |
| 競走成績(K) | 同 `www1.mbrace.or.jp/od2/K/` | 答え合わせ、学習(着順・進入コース・ST・展示・気象) | 毎朝 前日分の1ファイル |
| 潮位表(天文潮位の予測値) | 気象庁 `www.data.jma.go.jp/kaiyou/data/db/tide/suisan/txt/{年}/{地点}.txt`(地点は station{年}.php から各場の最寄り) | 海水・汽水の場の締切時刻の潮位と満ち引き(レース前に計算できる値) | 地点×年で1回だけ(約15地点) |
| アメダス最新観測 | 気象庁 `www.jma.go.jp/bosai/amedas/data/map/…json`(全国1ファイル) | 今朝の各場の最寄り地点の風。**今は貯めるだけで予想には未使用**(過去分が無く検証できないため。貯まったら同じ方法で検証する) | 毎朝1〜2ファイル |
| レーサー期別成績(ファン手帳データ) | 同 `boatrace.jp/static_extra/pc_static/download/data/kibetsu/fanYYMM.lzh`(レイアウト: boatrace.jp/owpc/pc/extra/data/layout.html) | コース別の1着率・2連対率・平均ST・平均スタート順位 | 年2回の公開ごとに1ファイル |

- 公式サイトのサイトポリシー(boatrace.jp/owpc/pc/extra/policy.html)の要点: 掲載内容は著作権で保護され、許諾なく私的使用などの範囲を超えて複製・頒布できない。「大量の情報送受信及び大量のアクセスなど、本サイトの運営に支障を与える行為」は禁止。ダウンロードページ自体には再配布や頻度についての個別の定めは無い(2026-10-24 確認)。
- そのため: **生ファイルは保存も公開もしない**(取得 → 展開 → 必要な数字だけ読み取り → 破棄)。読み取った数字(学習用の履歴 `hist/`)は Actions のキャッシュにだけ置き、公開リポジトリには入れない(`.gitignore`)。公開するのは予想・答え合わせ・集計とモデルの係数だけ。
- アクセスは控えめに: 毎朝は数ファイル。履歴づくりは 1ファイルごとに3秒あけ、1回の実行で上限あり(毎朝 最大40ファイル=20日分、手動 `backfill` は最大240ファイル)。一度取った日は取り直さない(データの無い日も記録する)。
- 気象庁のデータ: 気象庁ホームページの利用規約(政府標準利用規約(第2.0版)に準拠)により、出典を書けば複製・加工・公開できる。加工した場合はその旨を書く。数値データ・単純な表は著作物にあたらず自由に使えるとも書かれている(2026-10-25 確認: data.jma.go.jp の「当ホームページについて」)。自前で気象の予報はしない(気象業務法の予報業務にあたることはしない)。ページの出典欄に「気象庁ホームページ『潮位表』のデータを加工して作成」と書く(潮位を使っているとき)。
- 履歴の控え: Actions のキャッシュは7日間使われないと消えるので、読み取った数字(日ごとの json.gz、期別成績、潮位)を月ごとの束にして**非公開**リポジトリ `Hiro0530/arbitrage-scout` の `kyotei_data/` にも置く(`durable.py`)。リポジトリのシークレット `KYOTEI_DATA_TOKEN`(arbitrage-scout の Contents 読み書きだけの fine-grained トークン)があるときだけ動き、キャッシュに無い日をそこから戻す。無いときはキャッシュだけで動く。
- **直前情報のページ(展示タイム・当日の気象・部品交換・プロペラ)とオッズは取得しない。** レースごとのページを1日に何百回も読みに行くことになり「大量のアクセス」にあたるおそれがあるうえ、朝の公開時点では存在しないため。

## 特徴量(すべてレースの前に分かるもの)

`features.py`。日付順に1日ずつ進め、その日の朝の時点の情報だけで特徴量を作ってから、その日の結果を履歴に足す。

- 番組表: 全国勝率・全国2連率・当地勝率・モーター2連率・ボート2連率・級別・体重、レース内の相対値、今節のここまでの平均着順・F/事故の有無
- 過去の競走成績(前日まで、最長約3年): 選手の**枠別**1着率・2連対率(全体の枠別の率へ寄せて推定)、出走数、最近の1着率・3連対率(指数平滑)、**実際の進入コース別**1着率、平均ST(とレース内の相対値)、直近180日のフライング回数、前付け/コースを取られる率
- レーサー期別成績: 枠=コースとみなしたコース別の1着率・2連対率・平均ST・平均スタート順位。各期のファイルは期末の翌々月1日以降だけ使う(公開前の数字を使わないため)
- 気象: **前日の同じ場**の平均風速・波高(1号艇、4〜6号艇との組み合わせ)。当日の実測値は結果ファイルにしか無いので予想には使わない
- 場×枠の効果(全体の枠の効果へ寄せる)。平均ST・全国勝率・モーター2連率は枠ごとに効き方を変える

参考の検証だけに使うもの(oracle、予想には不使用): 当日の風速・波高・展示タイム。「もしレース前に分かったら、どれだけ良くなるか」を測るため。

## モデルと検証

- `model2.py`: 条件付きロジット(1レース6艇のsoftmax)、L2正則化、L-BFGS。3連単は Harville に2着・3着の補正(確率のλ乗)を入れ、λは学習外の予想で決める。勾配ブースティング(艇ごとの二値分類)も試したが、確率の精度(対数損失)と当たり具合が悪かったので採用していない。
- `train.py`: 直近6週について、1週ずつ「その週より前だけで学習 → その週を予想」(ウォークフォワード)。比較: 1号艇を毎回/場×枠の率だけ/番組表の数字だけのモデル(旧モデル相当)。1着的中率・単勝の仮の回収率・3連単3点の的中率・対数損失・Brier・確率の当たり具合(10区分)、1号艇との差のブートストラップ95%区間。結果は `model.json` の `eval`(読み取りの点検は `data_check`)に入り、ページに出る。
- 手元での検証: `python kyotei/train.py <histのフォルダ> [週数]`

## site_data.json の形(ページとXが使う数字。schema 1)

`site_data.py` が毎朝作り、`site_gen.py`(見た目だけ)はこれを読んでページを作る。見た目を変えるときは `site_gen.py` だけを直せばよい。金額はすべて円、確率は0〜1、時刻は日本時間の ISO 8601。

- `schema`, `generated_at`, `page_url`
- `today`(当日の予想。無ければ null): `date`, `published_at`(予想を公開した時刻。締切より前であることの証拠), `proof_url`(その日の予想ファイルの Git 履歴), `model_fitted_at`,
  `races[]`: `key`, `venue`(01〜24), `venue_name`, `race`, `close`(締切), `scored`(false=公開時刻より前に締切で採点しない), `tier`(自信度 S/A/B/C), `pick`(本命の枠), `p_pick`(本命の1着確率), `probs[6]`(1〜6号艇の1着確率), `trifecta[3]`(`[組番, 確率]`),
  `featured[]`(確率の高い6レースの key、締切順)
- `yesterday`(直近の答え合わせ): `date`, `proof_url`, `summary`(`graded_races`, `win_hits`, `tri_hits`, `near`, `base_hits`, `stake_win`/`return_win`/`pnl_win`(本命の単勝100円ずつ), `stake_tri`/`return_tri`/`pnl_tri`(3連単3点×100円), `stake_base`/`base_return`/`pnl_base`(1号艇の単勝100円ずつ)), `best_tri_hit`(その日の3連単の的中でいちばん高い払戻。無ければ null),
  `races[]`: `key`, `venue_name`, `race`, `tier`, `pick`, `trifecta[3]`, `actual`(結果 1-2-3着), `verdict`(的中/惜しい/1着的中/外れ), `win_hit`, `tri_hit`, `lane1_won`, `tansho_payout`(1着の単勝の払戻・100円あたり。古い記録には無い), `trifecta_payout`(3連単の払戻・100円あたり), `pay_win`, `pay_tri`, `base_pay`, `pnl_win`, `pnl_tri`, `pnl_base`, `pnl_race`(本命の単勝100円+3連単3点の増減)
- `record`: `total`(公開してからの累計: `days`, `graded_races`, `win_rate`, `base_win_rate`, `tri_rate`, `roi_win`, `roi_tri`, `roi_base`, 金額と `pnl_*`), `daily[]`(日ごとの summary、直近60日), `tiers_live`(自信度ごとの公開後の実績 `races`, `win_hits`, `base_hits`, `return_win`)
- `model`: `version`, `n_races`, `train_from`, `train_to`, `fitted_at`, `lambda`, `config`(`feats`, `tiers`=自信度のしきい値 `[名前, 本命の確率の下限]`), `features_used[]`, `not_used`, `uses_tide`,
  `eval`(学習外の検証): `test_from`, `test_to`, `test_days`, `full`/`base`/`prior`/`oracle`(`top1`, `logloss`, `roi_win`, `tri3_hit` など。`full.calibration` は `[平均の確率, 実際の1着率, 艇数]`), `lane1`, `diff_vs_lane1`(的中率の差と95%区間), `beats_lane1`, `tiers[]`(`tier`, `p_from`, `p_to`, `races`, `per_day`, `hit`, `hit_lo`, `hit_hi`, `lane1`, `roi_win`, `roi_lo`, `roi_hi`)
- `disclaimers[]`(必ずページに出す注意書き), `sources[]`(出典)

## 自信度(しきい値は学習外で決める)

- `exp_v3.py` が「選ぶ期間」の予想だけで、本命の確率が t 以上のレースの1着的中率が 75%(S)/65%(S+A)以上になるいちばん低い t を決め、`model_config.json` の `tiers` に書く。その後の「確かめる期間」と公開後の実績で評価する(しきい値を決めた期間の成績はページに出さない)。
- ページ・`site_data.json` には自信度ごとに、レース数・1日あたりのレース数・1着的中率(95%区間)・同じレースで1号艇を毎回選んだ場合・単勝の仮の回収率(95%区間)を出す。自信度が高いレースは1号艇の本命が多く、払戻が低いので、的中率が高くても回収率は100%を下回るのがふつう。

## v3 の改良候補と検証(`exp_v3.py`)

- 候補: 選手の最近30/90日の成績(枠ごとの期待との差)/選手×場/選手×枠×場(場×枠 → 選手×枠 → 選手×枠×場 と階層的に寄せる)/モーター番号ごとの最近の成績(乗った選手の力を差し引いた2連対。番組表の2連率が一斉に0になった日を入れ替えとみなす)/展示タイム(競走成績ファイルに載る。**前のレースまで**の値だけ使う): 選手の最近の展示、モーター番号ごとの展示(回り足の目安)、モーターの平均より良い展示・成績を出せているか(整備・ペラ調整の力の目安)/潮位(締切時刻の潮位と1時間の変化、場ごとに効き方を変える)/前日の風の向き(東西・南北の成分を場ごとの係数で。場ごとの水面の向きはデータから学ぶ)/場ごとの係数/アンサンブル(正則化の強さ・学習期間の違うモデルの対数確率の平均)。
- 方法: 直近16週を2つに分け、古い8週(選ぶ期間)で候補を1つずつ足し、**対数損失の差の95%区間(レース単位のブートストラップ)の上端が0未満のときだけ残す**。直近8週(確かめる期間)は選ぶのに使わず、最後に v2・1号艇と並べる。結果は `experiments/v3_ablation.json`(集計の数字だけ)。
- 参考(上限): 当日のレース時の風(向きつき)が前もって分かった場合の改善幅も測る。前もって分かる風(前日・今朝のアメダス)で得られる改善は、これより小さい。
- 音・回り足・ペラ: 音は測れない。部品交換・プロペラの情報は直前情報のページにしか無いので使わない(限界)。展示タイムとモーター番号ごとの成績で代わりに見る。

## オッズについて(使っていない)

オッズがあれば「AIの確率 × オッズ」が1を超える舟券(市場より高く見ている舟券)を探す、いわゆる期待値の判定ができる。払戻率が75%なので、的中率が1号艇を上回っても回収率は100%を下回るのがふつうで、利益の可能性を考えるならオッズとの比較が要る。ただし、オッズはレースごとのページを何度も読みに行く必要があり、公式サイトの「大量のアクセス」の禁止にあたるおそれがあるので**取得しない**。このためこの記録帳は「当たり具合」の記録で、儲かる買い方を示すものではない。

## 残っている限界

- 当日の展示タイム・直前の気象・進入の予想(前付け)・オッズは使えない(朝の公開時点で無い/取得しない)。
- 期別成績のコース別の数字は「枠=コース」とみなして使う(前付けがあるとずれる)。
- モーターの2連率は番組表の値(新モーターの入れ替え直後は当てにならない)。
- 履歴は Actions のキャッシュにあり、7日間使われないと消える。控え(`KYOTEI_DATA_TOKEN`)が設定されていればそこから戻し、無ければ毎朝少しずつ取り直す。
- 当日の展示タイム・直前の気象・部品交換・プロペラ・エンジン音は使えない(展示タイムは前のレースまでの分だけ)。
- アメダスの朝の観測は過去分が無く、貯まるまで検証できない(予想には未使用)。
